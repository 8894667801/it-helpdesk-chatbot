# Microsoft Outlook: 30 Advanced L3 Troubleshooting Fixes\n\n**Issue 1: Outlook Stuck on Loading Profile**\n**Symptoms:** Outlook hangs indefinitely at the splash screen showing 'Loading Profile'.\n**Root Cause:** Corrupt profile registry keys, hung Outlook process, or incompatible add-in.\n**Troubleshooting Steps:**\n- Kill hung processes: Open Task Manager and end any running OUTLOOK.EXE processes.\n- Start in Safe Mode: Run outlook.exe /safe. If it loads, disable all COM Add-ins and re-enable one by one.\n- Reset Navigation Pane: Run outlook.exe /resetnavpane.\n- Disable Hardware Acceleration: If able to load, disable hardware graphics acceleration in Options > Advanced.\n**Resolution:**\n- Recreate the Outlook Mail profile via Control Panel > Mail if Safe Mode fails to resolve the stuck screen.\n\n---\n\n**Issue 2: Outlook Application Crashing on Launch**\n**Symptoms:** Outlook opens briefly and closes immediately or throws a 'Microsoft Outlook has stopped working' error.\n**Root Cause:** Corrupted OST file, conflicting third-party antispam/antivirus add-ins, or corrupted Office installation.\n**Troubleshooting Steps:**\n- Event Viewer Check: Check Application event logs for Event ID 1000 pointing to the faulting module (e.g., ucrtbase.dll or add-in DLL).\n- Safe Mode Test: Launch holding CTRL to enter Safe Mode. If successful, remove faulting add-in.\n- Rename OST File: Navigate to %localappdata%\Microsoft\Outlook and rename the OST file to .old to force recreation.\n**Resolution:**\n- Perform an Online Repair of Microsoft 365 Apps or run Microsoft Support and Recovery Assistant (SaRA).\n\n---\n\n**Issue 3: Continuous Modern Auth / Password Prompts**\n**Symptoms:** User is constantly prompted for credentials or MFA, even after checking 'Remember my credentials'.\n**Root Cause:** Cached credentials conflicting in Windows Credential Manager, Modern Authentication disabled, or Primary Refresh Token (PRT) expiration.\n**Troubleshooting Steps:**\n- Clear Credential Manager: Open Windows Credential Manager and clear all Windows Credentials starting with MicrosoftOffice.\n- Clear Identity Cache: Delete keys under HKCU\Software\Microsoft\Office\16.0\Common\Identity\Identities.\n- Disconnect Work/School Account: Go to Settings > Accounts > Access Work or School, disconnect the M365 account, and reconnect.\n**Resolution:**\n- Force re-authentication by running <code>dsregcmd /status</code>, clearing cache, and signing back into Office apps.\n\n---\n\n**Issue 4: OST File Reach Maximum Size Limit**\n**Symptoms:** Errors stating 'The Outlook data file has reached the maximum size' or 'Cannot expand the folder'.\n**Root Cause:** The OST file has exceeded the default 50GB limit set by Outlook.\n**Troubleshooting Steps:**\n- Check Mailbox Size: Verify mailbox size in Exchange Online to see if the user is over their 50GB/100GB limit.\n- Adjust Cached Exchange Mode: Go to Account Settings and change the 'Keep mail offline for' slider from 'All' to '1 Year' or less.\n- Compact OST: Go to Data Files > Settings > Advanced > Outlook Data File Settings > Compact Now.\n**Resolution:**\n- Reduce cache slider duration, compact the OST file, or increase the MaxLargeFileSize registry key if absolutely necessary.\n\n---\n\n**Issue 5: Search Returning No Results / Incomplete Results**\n**Symptoms:** Searching in Outlook returns 'No results found' or only shows emails older than a specific date.\n**Root Cause:** Windows Search Index is corrupted or Outlook is unselected in Indexing Options.\n**Troubleshooting Steps:**\n- Check Indexing Status: Click Search > Search Tools > Indexing Status. Check if items are remaining to be indexed.\n- Verify Outlook is Indexed: Open Windows Indexing Options and ensure 'Microsoft Outlook' is checked.\n- Rebuild Index: In Indexing Options > Advanced, click 'Rebuild' (this may take several hours).\n**Resolution:**\n- If rebuilding fails, repair the Office installation or switch off 'Improve search speed by limiting the number of results shown'.\n\n---\n\n**Issue 6: Shared Mailbox Not Updating**\n**Symptoms:** Emails sent to a shared mailbox do not appear, or folders show outdated content compared to Outlook Web (OWA).\n**Root Cause:** Folders within the shared mailbox have hit the 500-folder limit, or the OST file is too large to sync changes efficiently.\n**Troubleshooting Steps:**\n- Compare OWA: Verify if the missing emails appear in OWA. If yes, it's a client sync issue.\n- Disable Download Shared Folders: Go to Account Settings > More Settings > Advanced. Uncheck 'Download shared folders'.\n- Update Folder Manually: Go to the Send/Receive tab and click 'Update Folder'.\n**Resolution:**\n- Unchecking 'Download shared folders' forces Outlook to read the shared mailbox directly from Exchange Online, resolving the sync issue.\n\n---\n\n**Issue 7: Cannot Open Shared Calendar or Permissions Error**\n**Symptoms:** Unable to view a colleague's calendar, or receiving 'You do not have permission to view this calendar' despite being given access.\n**Root Cause:** Calendar permissions not fully replicated in Exchange Online, or corruption in the local Free/Busy cache.\n**Troubleshooting Steps:**\n- Verify OWA Access: Check if the user can open the shared calendar in Outlook Web App.\n- Remove and Re-add: Right-click the calendar, select 'Delete Calendar', and re-add it from the Global Address List.\n- Check Exchange Permissions: Verify via Exchange Admin Center or PowerShell (Get-MailboxFolderPermission) that the user has Reviewer access or higher.\n**Resolution:**\n- Remove the calendar from the client. Enable 'Turn on shared calendar improvements' in Account Settings > Advanced, and re-add.\n\n---\n\n**Issue 8: Outlook Disconnected from Exchange**\n**Symptoms:** Status bar shows 'Disconnected' or 'Trying to connect...' continuously.\n**Root Cause:** Network DNS failure, proxy interfering with Autodiscover/MAPI, or stale network adapter configurations.\n**Troubleshooting Steps:**\n- Check Toggle Status: Ensure 'Work Offline' is not toggled ON in the Send/Receive ribbon.\n- Ping M365 Endpoints: Ping outlook.office365.com to verify DNS resolution.\n- Flush DNS: Run ipconfig /flushdns from Command Prompt.\n**Resolution:**\n- Re-authenticate using Modern Auth (clear credentials if needed) or switch networks (e.g., disconnect from VPN) to restore connection.\n\n---\n\n**Issue 9: Autodiscover Failing During Profile Setup**\n**Symptoms:** When adding a new account, Outlook fails to find the server settings automatically and errors out.\n**Root Cause:** Local AD SCP lookup failing in hybrid environments, or DNS CNAME for Autodiscover is misconfigured.\n**Troubleshooting Steps:**\n- Bypass SCP Lookup: Add Registry Key ExcludeScpLookup under HKCU\Software\Microsoft\Office\16.0\Outlook\AutoDiscover and set to 1.\n- Use Microsoft Remote Connectivity Analyzer: Run the Outlook Connectivity test at testconnectivity.microsoft.com to pinpoint DNS/Auth failures.\n- Create Profile via Mail Applet: Use Control Panel > Mail instead of the Outlook startup wizard.\n**Resolution:**\n- Bypass local AD SCP lookups via Registry or fix the external DNS Autodiscover CNAME pointing to <code>autodiscover.outlook.com</code>.\n\n---\n\n**Issue 10: Send/Receive Error 0x8004010F**\n**Symptoms:** Sending/receiving emails fails with error '0x8004010F: Outlook data file cannot be accessed'.\n**Root Cause:** Corrupted Outlook profile or the OST/PST file is no longer accessible/linked correctly.\n**Troubleshooting Steps:**\n- Locate Data File: Go to Account Settings > Data Files. Check the exact path of the default delivery location.\n- Re-link Data File: Click 'Change Folder' on the Email tab, select a temporary folder, then change it back to the correct Inbox.\n- Run SCANPST: If the file is a PST, run SCANPST.EXE to repair file structure.\n**Resolution:**\n- Create a completely new Outlook Mail Profile and let Exchange recreate the fresh OST file to permanently fix the link.\n\n---\n\n**Issue 11: Missing Folders / Folders Not Visible**\n**Symptoms:** User creates a folder in OWA or another device, but it does not appear in the Outlook Desktop client.\n**Root Cause:** Folder hierarchy sync failure or 'Folder View' is filtered.\n**Troubleshooting Steps:**\n- Check Folder List Mode: Press CTRL + 6 to switch to 'Folder List' view to see if it's hidden under a different parent.\n- Reset View: Run outlook.exe /cleanviews to reset all custom folder views.\n- Clear Offline Items: Right-click the Inbox or parent folder > Properties > General > click 'Clear Offline Items', then Update Folder.\n**Resolution:**\n- Clear Offline Items on the parent folder to force Outlook to re-download the folder hierarchy from Exchange.\n\n---\n\n**Issue 12: Out of Office (OOF) Not Saving / Server Unreachable**\n**Symptoms:** Clicking Automatic Replies shows 'Your automatic reply settings cannot be displayed because the server is currently unavailable'.\n**Root Cause:** EWS (Exchange Web Services) is blocked or the primary SMTP address does not match the UPN in a hybrid setup.\n**Troubleshooting Steps:**\n- Check via OWA: Verify if OOF can be set via Outlook Web App. If yes, the issue is client-side EWS connection.\n- Check Connection Status: CTRL + Right-click Outlook icon in system tray > Connection Status. Check for EWS connection failures.\n- Verify Autodiscover: Run 'Test E-mail AutoConfiguration' (CTRL + Right-click tray icon) and check the OOF URL.\n**Resolution:**\n- Correct UPN/Primary SMTP mismatch in Active Directory, or bypass proxy servers blocking EWS endpoints.\n\n---\n\n**Issue 13: Outlook Rules Not Firing / Corrupted**\n**Symptoms:** Emails are not being moved to folders automatically, or opening Rules gives an error about space limitations.\n**Root Cause:** Exceeded the 256KB rules quota limit in Exchange, or rules contain corrupted 'client-only' actions.\n**Troubleshooting Steps:**\n- Check Rules Quota: Increase rules limit via PowerShell: Set-Mailbox -RulesQuota 256KB (if at 64KB).\n- Export and Delete: Export rules to an .rwz file as a backup, then run outlook.exe /cleanrules to wipe all local/server rules.\n- Recreate Rules from OWA: Recreate critical server-side rules in OWA to ensure they run even when Outlook is closed.\n**Resolution:**\n- Wipe corrupted rules using `/cleanrules` and recreate them, preferably Server-side via OWA, keeping under the quote limit.\n\n---\n\n**Issue 14: Address Book (OAB) Not Updating**\n**Symptoms:** New hires do not show up in the Outlook Address Book, or user details (phone/title) are outdated.\n**Root Cause:** Offline Address Book (OAB) is out of sync or failed to download from the Exchange server.\n**Troubleshooting Steps:**\n- Force Download: Go to Send/Receive > Send/Receive Groups > Download Address Book. Uncheck 'Download changes since last Send/Receive'.\n- Delete Local OAB files: Navigate to %localappdata%\Microsoft\Outlook\Offline Address Books and delete the folder contents.\n- Check OWA: Verify the Global Address List in OWA. If correct there, the client needs fresh OAB generation.\n**Resolution:**\n- Deleting the local OAB files and forcing a full manually download forces Outlook to rebuild the address list from scratch.\n\n---\n\n**Issue 15: Freezing When Typing or Switching Folders**\n**Symptoms:** Outlook frequently shows 'Not Responding' for a few seconds when switching folders or composing emails.\n**Root Cause:** Large OST file, high folder count, or aggressive antivirus scanning of OST files in real-time.\n**Troubleshooting Steps:**\n- Exclude OST from AV: Ensure anti-virus is configured to exclude *.ost and *.pst files from real-time scanning.\n- Reduce Cached Time: Slider to 6 months or 1 year in Cached Exchange Mode settings.\n- Check Add-ins: Disable CRM, PDF, or dictation add-ins temporarily to see if performance improves.\n**Resolution:**\n- Reduce OST size and add AV exclusions for Outlook data files.\n\n---\n\n**Issue 16: Third-Party Add-in Disabling Repeatedly**\n**Symptoms:** A required add-in (like Salesforce, Zoom, or Teams) gets disabled every time Outlook restarts.\n**Root Cause:** Outlook detects the add-in slowing down startup by more than 1000ms and hard-disables it.\n**Troubleshooting Steps:**\n- Force Enable in Outlook: Go to File > Slow and Disabled COM Add-ins. Select 'Always enable this add-in'.\n- Modify Registry Resiliency: Navigate to HKCU\Software\Policies\Microsoft\Office\16.0\Outlook\Resiliency\AddinList. Add a String value with the Add-in ProgID and set it to '1' (Always Enabled).\n**Resolution:**\n- Deploy the 'Always Enable' registry key via Group Policy/Intune to prevent Outlook from auto-disabling critical business add-ins.\n\n---\n\n**Issue 17: Licensing Errors / Unlicensed Product**\n**Symptoms:** Title bar says '(Unlicensed Product)' and functionality is restricted to Read-Only mode.\n**Root Cause:** Cached activation tokens are invalid, or computer has lost trust with Azure AD.\n**Troubleshooting Steps:**\n- Sign out of Office: In Word/Outlook, go to File > Account > Sign Out, and close all Office apps.\n- Run OSPP.vbs script: Run cscript ospp.vbs /dstatus to find the 5-digit product key and use /unpkey:XXXXX to remove stale keys.\n- Clear BrokerPlugin Data: Rename the identity folder in %localappdata%\Packages\Microsoft.AAD.BrokerPlugin...\n**Resolution:**\n- Clear old licenses using OSPP.vbs, clear Windows Credentials, and sign back in to force a fresh activation token from M365.\n\n---\n\n**Issue 18: Attachments Blocked or Cannot Open**\n**Symptoms:** Replaces attachments with 'Outlook blocked access to the following potentially unsafe attachments'.\n**Root Cause:** File type is restricted (e.g. .exe, .js, .mde), or temporary internet files folder is full/corrupt.\n**Troubleshooting Steps:**\n- Clear OutlookSecureTempFolder: Lookup OutlookSecureTempFolder in Registry, navigate to that path, and delete all contents.\n- Zip the File: Instruct sender to compress restricted extensions into a .zip file.\n- Unblock Level 1 Files: If business-critical, modify Level1Remove registry key to allow specific extensions (Not recommended for security).\n**Resolution:**\n- Clear the SecureTempFolder registry path contents if attachments give 'Cannot create file' errors. Otherwise, zip restricted files.\n\n---\n\n**Issue 19: Reminders Not Popping Up**\n**Symptoms:** Meeting reminders fail to pop up, causing users to miss scheduled meetings.\n**Root Cause:** Corrupted reminders folder or Windows Focus Assist blocking notifications.\n**Troubleshooting Steps:**\n- Clean Reminders: Close Outlook and run outlook.exe /cleanreminders.\n- Check Windows Notifications: Go to Windows Settings > System > Notifications. Ensure Outlook notifications are ON and Focus Assist/Do Not Disturb is OFF.\n- Verify Outlook Setting: File > Options > Advanced. Ensure 'Show reminders' is checked.\n**Resolution:**\n- Running `/cleanreminders` recreates the internal reminders queue and usually restores proper popup functionality.\n\n---\n\n**Issue 20: Sent Items Not Saving in Shared Mailboxes**\n**Symptoms:** When sending 'As' a shared mailbox, the sent email goes to the User's primary Sent Items, not the Shared Mailbox Sent Items.\n**Root Cause:** By default, Outlook saves items sent as a delegate to the primary mailbox.\n**Troubleshooting Steps:**\n- Registry Fix for Sent Items: Add DWORD DelegateSentItemsStyle = 1 in HKCU\Software\Microsoft\Office\16.0\Outlook\Preferences.\n- Exchange PowerShell Fix: Run Set-Mailbox -Identity shared@domain.com -MessageCopyForSentAsEnabled $true as Admin.\n**Resolution:**\n- Use the Exchange PowerShell command (preferred enterprise method) to automatically copy sent items into the Shared Mailbox Sent folder.\n\n---\n\n**Issue 21: Recovering Deleted Items Fails**\n**Symptoms:** User accidentally shift-deleted an email and it cannot be found in the Deleted Items folder.\n**Root Cause:** Item has moved to the Recoverable Items (Dumpster) partition.\n**Troubleshooting Steps:**\n- Open Recover Deleted Items: Go to Folder tab > click 'Recover Deleted Items'.\n- Search via OWA: Sometimes OWA's Recover Deleted Items interface is more reliable than the Outlook client.\n- Admin eDiscovery: If past the 14-day default window, an Admin must perform an eDiscovery search (if Litigation Hold is enabled).\n**Resolution:**\n- Select the item in the 'Recover Deleted Items' dialog and choose 'Restore Selected Items'. It goes back to the original folder.\n\n---\n\n**Issue 22: Teams Meeting Add-in Missing**\n**Symptoms:** The 'New Teams Meeting' button disappears from the Outlook Calendar ribbon.\n**Root Cause:** Add-in was disabled by Outlook for load times, or Teams was installed without Admin privileges.\n**Troubleshooting Steps:**\n- Re-enable in Add-ins: File > Options > Add-ins. Change Manage drop-down to Disabled Items, click Go. Re-enable Teams Add-in.\n- Re-register DLL: Close Outlook. Re-register Microsoft.Teams.AddinLoader.dll using regsvr32.\n- Restart Teams: Fully quit Teams from system tray, restart Teams, then restart Outlook.\n**Resolution:**\n- Go to Disabled Items, re-enable the Microsoft Teams Meeting Add-in, and check the COM Add-ins list to ensure it is checked.\n\n---\n\n**Issue 23: Signatures Missing After Upgrading**\n**Symptoms:** Clicking the Signature button does nothing, or all previous signatures are gone.\n**Root Cause:** Microsoft's new 'Cloud Roaming Signatures' feature conflicts with locally stored `%appdata%\Microsoft\Signatures`.\n**Troubleshooting Steps:**\n- Check Local Path: Verify if the `.htm` and `.rtf` signature files still exist in the AppData pathway.\n- Disable Roaming Signatures: Set Registry DWORD DisableRoamingSignaturesTemporaryToggle = 1 under HKCU\Software\Microsoft\Office\16.0\Outlook\Setup.\n- Recreate Signatures: If missing completely, the user must recreate them via File > Options > Mail > Signatures.\n**Resolution:**\n- Add the Registry key to disable Cloud Signatures if enterprise local-signature scripts are failing to apply.\n\n---\n\n**Issue 24: Mail Stuck in Outbox**\n**Symptoms:** Emails sit in the Outbox and show a status of transmitting but never leave.\n**Root Cause:** An email with a huge attachment is choking the queue, or the OST file is corrupted.\n**Troubleshooting Steps:**\n- Work Offline: Go to Send/Receive tab, click 'Work Offline'. Restart Outlook.\n- Move/Delete Stuck Email: While offline, open the Outbox, move the stuck email to Drafts or delete it. Turn off 'Work Offline'.\n- Check Attachment Size: Ensure attachments do not exceed the 35MB standard Exchange limit.\n**Resolution:**\n- Toggle to Work Offline mode to release the lock on the Outbox, delete the large email, and reconnect to clear the queue.\n\n---\n\n**Issue 25: VPN / Proxy Blocking Connection**\n**Symptoms:** Outlook is disconnected when working remotely on VPN, but works fine on the corporate network.\n**Root Cause:** Split-tunneling is misconfigured, or MTU size over VPN truncates Outlook RPC/MAPI packets.\n**Troubleshooting Steps:**\n- Test Off-VPN: Disconnect from VPN. If it connects, the VPN firewall is blocking M365 IPs.\n- M365 Network Connectivity Test: Run connectivity.office.com to verify proxy bypass rules are active for Optimize category endpoints.\n- Check Proxy Settings: Ensure 'Bypass proxy server for local addresses' is set in Internet Options.\n**Resolution:**\n- Work with the Network team to bypass all Microsoft 365 <code>Optimize</code> endpoints from VPN forced-tunneling and SSL Inspection.\n\n---\n\n**Issue 26: New Outlook Toggle Reverting to Classic**\n**Symptoms:** User tries to toggle 'Try the New Outlook', but it immediately flips back or fails to install.\n**Root Cause:** The New Outlook installation is blocked by Group Policy, AppLocker, or the mailbox is hosted on an unsupported On-Premise Exchange.\n**Troubleshooting Steps:**\n- Verify Exchange Hosting: Ensure the mailbox is fully migrated to Exchange Online (M365). New Outlook does not support legacy on-prem servers yet.\n- Check GPO: Verify if the registry key HideNewOutlookToggle is set to 1.\n- Manual Install: Install 'Outlook for Windows' manually from the Microsoft Store.\n**Resolution:**\n- Ensure mailbox is M365-hosted and manually install the UWP Outlook app from the Store if the toggle is broken.\n\n---\n\n**Issue 27: Images Not Downloading in Emails**\n**Symptoms:** Emails display red 'X' icons instead of pictures. Clicking 'Download Pictures' does nothing.\n**Root Cause:** Trust Center settings restrict auto-download, or the IE/Edge temporary internet cache path is invalid.\n**Troubleshooting Steps:**\n- Trust Center Check: File > Options > Trust Center > Trust Center Settings > Automatic Download. Uncheck 'Don't download pictures automatically'.\n- Check IE Cache: In Internet Options > General > Browsing history settings, check if the Current location path is valid. Move the folder to Default if necessary.\n**Resolution:**\n- Fix the corrupted Internet Temporary Files folder path in Windows Internet Options, which Outlook uses to process downloaded images.\n\n---\n\n**Issue 28: Font Size Changes Suddenly / Zoom Issue**\n**Symptoms:** The text in the Reading Pane or composed emails is extremely tiny or huge.\n**Root Cause:** The Zoom level in the reading pane was accidentally changed with CTRL + Mouse Wheel.\n**Troubleshooting Steps:**\n- Reset Zoom via Ribbon: Open an email, go to the Message/Format Text tab, click Zoom, and select 100%.\n- Mouse Wheel Fix: Click inside the Reading Pane, hold CTRL, and spin the mouse wheel to resize text dynamically.\n- Zoom Slider: Check the bottom right corner of the Outlook window for the Zoom slider.\n**Resolution:**\n- Set Zoom back to 100% and tick 'Remember my preference' so it applies to all future emails.\n\n---\n\n**Issue 29: Delegation: 'Cannot open the folders' Error**\n**Symptoms:** An assistant (Delegate) gets 'Cannot open the folders' when trying to manage their manager's Inbox.\n**Root Cause:** Delegate given access to Inbox, but NOT given 'Folder Visible' permission on the Root Mailbox folder.\n**Troubleshooting Steps:**\n- Set Root Permissions: Manager must right-click their main email address at the top of the folder list > Properties > Permissions > Add Delegate > assign 'Folder visible' only.\n- Verify Inbox Permissions: Ensure the actual Inbox folder has Editor access assigned.\n- Restart Client: Delegate restarts Outlook to pull updated ACLs.\n**Resolution:**\n- Assign 'Folder Visible' permission on the 'Top of Information Store' (Root folder) to allow the delegate to map the subfolders correctly.\n\n---\n\n**Issue 30: PST Password Lost or Forgotten**\n**Symptoms:** User opens an Archive .pst file but doesn't know the password locking it.\n**Root Cause:** User set a password on their personal local archive and forgot it.\n**Troubleshooting Steps:**\n- Third-Party Tools: Microsoft does NOT provide a native PST password recovery tool. A third-party tool like 'NirSoft PstPassword' is required to strip the hashing.\n- Compliance Check: Verify enterprise security policy before running password-cracking tools on PST files.\n- Restore from Backup: If cracking fails, check Volume Shadow Copies (Previous Versions) prior to the password being set.\n**Resolution:**\n- Use authorized third-party recovery utilities to strip the weak CRC32 hash from the PST file if corporate policy permits.\n\n---\n\n
